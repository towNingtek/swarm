# deploy/

Run Swarm on one Linux host with systemd, Docker and nginx.

| Path | What it is |
|---|---|
| `install.sh` | One-time setup as root: `swarm` user, directories, settings file, generated secrets, units |
| `platform.env.example` | Settings, copied to `/etc/swarm/platform.env` |
| `bin/swarm-run` | Starts the platform, admin or relay with its settings and only its own secrets |
| `bin/swarm-site-firewall` | iptables rules for the isolated site network (root) |
| `bin/swarm-nginx-apply` | Applies site nginx configs that the platform stages (root) |
| `systemd/` | Units for the three services, the firewall and the nginx watcher |
| `nginx/swarm-platform.conf.example` | nginx for the platform origin |
| `tests/` | Checks for the scripts above; they run in throwaway containers |

## Layout on the host

| Path | Owner | Contents |
|---|---|---|
| `/opt/swarm` | root | This repository and its Python venv (`.venv`) |
| `/etc/swarm/platform.env` | root:swarm 0640 | Settings |
| `/etc/swarm/secrets/` | root:swarm 0750 | One file per secret, below |
| `/var/lib/swarm/platform` | swarm | SQLite database |
| `/var/lib/swarm/sites` | swarm | One directory per site |
| `/var/lib/swarm/nginx-staging` | root:swarm 0770 | Configs handed from the platform to the root watcher |

Secrets (`/etc/swarm/secrets/`):

| File | Needed by | Notes |
|---|---|---|
| `entry-secret` | platform, admin | Generated by `install.sh` |
| `admin-password` | admin | Generated by `install.sh` |
| `model-key` | all three | Key for your OpenAI-compatible model gateway |
| `cloudflare-token` | platform, admin | Optional, for automatic DNS records |
| `discord-token` | platform | Optional, for "a customer needs a human" pings |

## Install

```sh
sudo git clone https://github.com/towNingtek/swarm /opt/swarm
cd /opt/swarm
sudo python3 -m venv .venv && sudo .venv/bin/pip install -r requirements.txt
sudo docker build -f site/Dockerfile -t swarm-site:latest .
sudo deploy/install.sh
sudo editor /etc/swarm/platform.env          # domain, origins, model gateway
sudo editor /etc/swarm/secrets/model-key
sudo cp deploy/nginx/swarm-platform.conf.example /etc/nginx/conf.d/swarm-platform.conf
sudo editor /etc/nginx/conf.d/swarm-platform.conf && sudo nginx -t && sudo systemctl reload nginx
sudo deploy/install.sh --start
```

Then open `https://<platform>/admin` and sign in with the password from `/etc/swarm/secrets/admin-password`.

Requirements: Ubuntu 22.04 or similar, Docker 24+, nginx, Python 3.10+, about 2 GB of disk for the site image plus room for sites. TLS must end in front of nginx (certbot, a load balancer or a tunnel); the session cookies are `Secure`, so plain HTTP logins do not work.

## First customer

In the admin console: create a tenant with its host (`acme.<domain>`), set a quota, queue the site build and copy the invite link. The customer opens the link, picks a username and password, and the onboarding page shows the build. When it reads *ready*, **Open my site** hands them into their site without a second password.

Behind the scenes the build takes about a minute: container, nginx config through the watcher, DNS (if Cloudflare is set), the starter model key and the office template. Deleting the tenant in the console removes all of them.

DNS: point `platform.<domain>` and `*.<domain>` at the host (or a tunnel in front of it). If you set `CLOUDFLARE_ZONE_ID` and `secrets/cloudflare-token`, the platform creates each site's record itself.

## Logs

`journalctl -u swarm-platform -u swarm-platform-admin -u swarm-site-relay`. HTTP access logs are off on purpose: invite links carry their token in the URL.

## Security notes

- The `swarm` user is in the `docker` group, which is equivalent to root. Use a host dedicated to Swarm.
- The platform never runs `sudo`. Two small root pieces do the privileged work: the firewall unit, and the nginx watcher. The watcher only accepts `swarm-site-<name>.conf`, regular files up to 64 KiB, never follows links, keeps its own ownership records in a root-only directory, refuses to overwrite or remove configs it did not create, and restores the previous config if `nginx -t` fails.
- Root scripts read their few settings from `platform.env` as text. They never execute it, and they validate each value.
- Sites run on an isolated network. They can reach the internet and the model relay, but no other host port, private network or cloud metadata service. Check the rules with `sudo iptables -S SWARM-SITES-IN`.
